# Информационная система LabWork

Управление объектами `LabWork` и связанными `Coordinates`, `Discipline`, `Person`, `Location`.
Сервер: Jakarta EE 10, CDI, JAX-RS, EclipseLink. Клиент: React. База: PostgreSQL.
Изменения пишутся на сервере и сразу расходятся по открытым браузерам через WebSocket.

## Запуск

Нужны Docker и Docker Compose.

```powershell
docker compose up --build
```

Откройте http://localhost:8080

Первый запуск скачивает образы и собирает приложение, это несколько минут.
PostgreSQL публикуется на порту 5432, API Payara — на 8081. Интерфейс ходит в API через nginx, отдельно открывать 8081 не нужно.

Остановка с удалением данных:

```powershell
docker compose down -v
```

## Учётные записи

| Логин | Пароль | Что можно |
| --- | --- | --- |
| admin | admin | просмотр, создание, изменение, удаление, операции, меняющие данные |
| viewer | viewer | только просмотр и операции чтения |

Регистрация создаёт пользователя с ролью просмотра. Роль администратора через форму не выдаётся.

Чтобы увидеть живое обновление, войдите администратором в обычном окне и `viewer` в приватном окне.

## База

В Docker сервис называется `pg`, база `studs`, пользователь и пароль `studs`.
Так совпадает требование кафедрального сервера: хост `pg`, база `studs`.
На кафедральном сервере в `backend/src/main/webapp/WEB-INF/glassfish-resources.xml` нужно подставить свой пароль.

Схема и функции лежат в `db/init.sql`. При первом старте контейнера создаются 12 демонстрационных работ, поэтому на списке сразу видна пагинация.

## Как устроены операции

- Список, создание, карточка по id и диалог изменения — отдельные экраны. В меню: список, новая работа (только администратор), специальные операции.
- В таблице есть все атрибуты `LabWork`. Фильтр и сортировка — по строковым колонкам, фильтр только по полному совпадению.
- Координаты, дисциплина, автор и локация выбираются или создаются в форме работы. Отдельных экранов у них нет. Удаление выбранного объекта, если на него есть ссылки, просит замену.
- Если удаляемая работа входит в программу дисциплины, нужно выбрать другую работу: она займёт место в программе.
- Программа дисциплины — отдельная связь многие-ко-многим. Она не заменяет поле `LabWork.discipline`.
- Специальные операции вызывают функции PostgreSQL: `avg_minimal_point`, `lab_works_by_description`, `unique_minimal_points`, `decrease_labwork_difficulty`, `add_hardest_labworks`.

Сложность понижается по шкале `TERRIBLE → IMPOSSIBLE → VERY_HARD → HARD → NORMAL`. Ниже `NORMAL` функция базы возвращает ошибку. Десять самых сложных выбираются по этой шкале, при равенстве — по большему `minimalPoint`.

## Сборка интерфейса отдельно

Если поднят только `pg` и `backend`:

```powershell
cd frontend
npm install
npm run dev
```

Интерфейс разработки: http://localhost:5173 , запросы проксируются на порт 8081.
